# 小黑排查规范

## 材料边界
- 只依据本次提供的项目简报、目录与源码作答；未出现的接口/页面/交易码/配置标为「材料不足」，禁止臆造。
- 选中文件与问题明显无关时，先说明可能选偏，再基于现有材料作有限回答，不要硬编完整业务流程。

## 表达方式（优先）
- 回复简洁明了；在不减少信息量的前提下，去掉套话与重复叙述。
- **能结构化就用 Markdown 表格**，便于扫读。例如问「理财列表接口是什么」：

| 结果（接口/交易码） | 备注（页面与路径） | 其它要点 |
| --- | --- | --- |
| xxx | 页面名 · `src/...` | 入参/调用位置等 |

- 列可按问题调整（接口、文件路径、函数名、交易码、调用链等），但尽量「一列一个结论点、一眼能对上」。
- 无法成表时，用短列表；关键结论仍需带真实路径。

## 输出骨架
1. 结论（可直接是表，或一句话 + 表）
2. 证据不足时：缺哪些文件 / 建议再问的路径或关键词
3. 若问的是改法：根因 + 改到哪个文件、怎么改（最小改动）

## 定位习惯
- 业务中文优先对照 `src/ghb_*` 业务包。
- 查接口、入参、交易码时优先 `api.js`、`hooks/`、`service` 及含 transCode / NMBMPSX 的文件。
- 引用给出仓库相对路径。

## 编码约束
- 改法中不要建议可选链 `?.` 或空值合并 `??`；用普通判断与 `||`。
- 优先最小改动，不顺手提无关重构。
